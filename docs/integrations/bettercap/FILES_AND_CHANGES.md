# Cerberus Bettercap Integration - Added Files and Changes

## Integration summary

Bettercap is integrated as a new, isolated component. The supplied source archive already included the Scapy integration. The Bettercap addition preserves that Scapy work and all other pre-existing project files.

The command-line flow accepts one HTTP(S) URL, resolves one IPv4 address, and uses Bettercap's documented `net.recon` module to inspect the local ARP table for that IP. The module's documented behavior is to read the local ARP table periodically; it is not a remote website scanner. No active scanning, packet sniffing, spoofing, proxying, credential harvesting, or wireless attack command is generated by this integration.

## Existing files modified

**None.** No pre-existing source, configuration, documentation, wrapper, test, or project file was edited. All Bettercap-specific documentation and runtime files are new files under the dedicated integration paths.

## First-run installation design

The repository does not include a separately downloaded Bettercap binary. At first run, the included Python bootstrapper queries the official GitHub release API for the pinned tag `v2.42.0`, picks the archive matching the local operating system and CPU architecture, downloads it, optionally verifies the GitHub release digest, and extracts only `bettercap` / `bettercap.exe` into the ignored `.runtime/` directory. This keeps the source repository portable and avoids asking every contributor to manually clone Bettercap.

The configured official prebuilt targets are Windows amd64, Linux amd64, and macOS arm64. Platform-specific packet drivers or privileges remain system prerequisites; on Windows, Npcap must be installed separately when packet-capture support is required.

## How to run

```powershell
python tools/integrations/bettercap/cli.py
```

Enter a permitted HTTP(S) URL, then type `I HAVE AUTHORIZATION`. The target URL is resolved to one IPv4 address, and Bettercap runs only the fixed `net.recon` / `net.show` local ARP inspection sequence. Output is shown in the terminal and saved under `tools/integrations/bettercap/reports/`.

## Verification performed for this integration

- Python source compilation.
- Unit tests with mocked DNS and mocked Bettercap process execution.
- CLI `--help` smoke test.
- Safe command assertion: generated command includes only `net.recon`, `sleep`, `net.show`, and `q`.
- Existing archive-file byte comparison to verify no original file changed.
- ZIP integrity test after packaging.

The executable download and live Bettercap/Npcap execution are not performed during offline build verification; they occur on the user's first run on a supported computer.
